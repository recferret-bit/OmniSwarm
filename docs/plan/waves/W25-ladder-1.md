## Goal

Put a real check in front of every finding, and stop treating agreement as proof. Runs 1 and 2 show the current stages never lowered a status (`M1`–`M3`: 498 cross-check verdicts and 21 challenge turns, none against a finding), and two-vendor agreement confirmed decoys without a look (`M12`; models make correlated mistakes, `E11`).

Behind `--verify ladder` (default stays `debate` until W30):

- **Level 0, mechanical:** the citation check as today, plus host-built context for the verifier: the enclosing function, the control-like names in scope, the callers, the scanner hits. Read-only, no process spawned, shown to the verifier inside a fenced "untrusted source" block.
- **Level 1, blind verification of every cluster.** A verifier that did not see the author's reasoning, who reported it, how many did, or another verifier's answer (`E14`). It answers three questions with citations: is the path reachable, is the control really absent, is the impact as stated.
- **Who may verify.** In run 2, 28 of 63 clusters were authored by all three vendors and only 24 by one (`M18`), so a cross-vendor rule alone leaves 44% of clusters unverifiable. The tiers, in order: (1) vendors that did not author the cluster, (2) a pool member (W27), (3) a **fresh blind session of an author vendor**, recorded `same_vendor_fresh`. Tier 3 counts as a check but can lift a cluster to CONFIRMED only when at least two vendors authored it; otherwise it leaves LIKELY.
- **Agreement becomes a prior, not a verdict,** and **`partial` narrows, it does not support.**
- **Contested clusters** (a verifier refutes with a valid control citation) go to the existing challenge, defence and judge path with the verifier's answer as the round-1 turn. W26 replaces that path.

## Demo story (the check in words)

1. `./bin/audit run --repo engine/eval/twins/fullstack-dapp-fixed … --verify ladder --plan` → the plan lists cross-check `skipped (ladder)`, levels 0 and 1, the verifier tiers and the batch size, and says it is a Docker-path feature.
2. A scripted orchestrated run with `--verify ladder`: `verification/<batch>.json` exists for every cluster, `debate/adjudication.json` rows carry `depth`, `prior`, `independence` and, for a `partial` answer, `narrowed: true`. No row is `AGREED`.
3. A scripted **rubber-stamp** verifier over the canary set → catch rate 0 and a `rubber_stamp` warning in the scorecard. A scripted **perfect refuter** → 1.0. After the run, `grep -r <canary id>` over every report-visible file → nothing.
4. The scripted fixture with no flag → byte-identical findings and adjudication to before this wave.
5. The brief of a verifier session holds title, severity, location, impact and the context block, and none of the author's analysis, preconditions, vendor names, claim ids or reporter count.

## Risks and rollback

- **A blind verifier can still defer to the claim.** The scorecard's `fp_catch_rate` and the canary set measure it, and the spike is the kill switch.
- **Tier 3 (a fresh session of an author vendor) shares that vendor's mistakes** (`E11`). It cannot lift a one-vendor cluster to CONFIRMED, it is labelled in every row, and the pool (W27) replaces it where configured.
- **Context built by heuristics can miss a control, and it is text from the target.** It sits in a fenced untrusted block, the verifier has read tools, and the spike compares context only against tools.
- **Verifying every cluster costs more** (63 against 24 clusters debated in run 2). Batching by file is the mitigation; T6 caps tokens per kept finding.
- **A wrongly verified refutation hides a real bug.** A refutation needs a valid control citation; W26-00 measures the irrelevant-citation case before a refutation can lower a status.
- **Hidden canaries could leak.** The scrub list is explicit and a test greps every artifact on it.
- Rollback: default stays `--verify debate`; the legacy path was edited only in `debate-cluster` and `debate-rules` behind the mode parameter, with the legacy golden as the guard.
