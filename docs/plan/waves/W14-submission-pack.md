## Goal

A Claude Code or Codex screener that clones the repo and follows the README **runs every step without paid keys and sees what the README says** (`./bin/audit demo`). A human judge reads, in one screen, what OmniSwarm is, why NEAR matters to it, what is real and what is mock, and can open the hosted demo, a sample report, a dogfood report of OmniSwarm on its own contract with its on-chain attestation, and the guard attack log. The owner has every form field, the X post and the video script ready to paste, and submits before 20:00 UTC on 2026-11-14.

## Demo story (the check in words)

1. In a clean temp directory: `git clone <repo> && cd OmniSwarm && tools/screener-check.sh` with Docker stopped and no provider key in the environment → every README block marked `<!-- screener -->` runs and its "you should see" line matches; exit 0.
2. Open `README.md` on GitHub → the first screen says what it is, the problem, and a three-line "try it" (`npm ci`, `./bin/audit demo`, open `reports/<run>/report.html`) with "you should see" lines; then the hosted demo link, the sample report link and the dogfood report link.
3. Scroll to **NEAR** → a mock/real table (login, signed request, payment, attestation, guard, reviewer sub-accounts) with the testnet contract id and explorer links.
4. Scroll to **Hackathon baseline** → baseline = commits up to `94551b9` (2026-10-17), new work = the compare link `pre-hackathon...hackathon-submission`, and a list of what was built in the window.
5. Open `RULES.md` → the swarm rules: phases, fixed passes and tool budget, anonymized debate, citation rule, conformity flag, cross-family judge, statuses, stop conditions, and a text sequence diagram of one debate round.
6. Open the dogfood report link → `reports.<domain>/dogfood/report.html` with per-model pages, cross-check and general review; its attestation badge on the landing matches the testnet `attest` tx.
7. Open `docs/hackathon/SUBMISSION.md` → every form field filled except `nearAddress` (owner placeholder), `idea` ≤ 2000 characters (counted), track ids, the X post text, and a validated JSON body ≤ 12 000 bytes with no `website` field.
8. Run `tools/secret-sweep.sh` → no secret in the full git history, no `reports/`, `pocs/` or `.env` tracked.
9. The owner records the video from `docs/hackathon/VIDEO.md`, posts on X, makes the repo public, submits the form, and pushes `hackathon-submission`.
