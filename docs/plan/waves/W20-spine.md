## Goal

Land, once and early, the seams and tools that let every later wave add files instead of editing shared ones:

- **One execute seam.** On the Docker path every agent session passes through `createExecute` (`engine/scripts/orchestrator-session.mjs`, wired at `docker-agent-orchestrator.mjs:147`). A middleware registry (`orchestrator-mw-*.mjs`, discovered like `report-section-*.mjs`) lets telemetry, lanes, retries and budgets wrap it with no further edit to the orchestrator. The host path (`--no-docker`, `review-host.mjs`) calls `runReviewSession` directly and is **not** covered; every feature of this series runs on the Docker path, and neutrality tests drive `runOrchestratedAudit` with an injected scripted `review` and `startSandbox`, as `docker-agent-orchestrator.test.mjs` does.
- **One event log,** `harness/host/events.jsonl`, one `run-event` per line, host-only, every field an enum, a number or a bounded identifier.
- **Structured token usage** summed over every `session/prompt` result of a session, so cost no longer has to be read out of logs (a log keeps only the last process's frame, `M10`).
- **Reserved flags, config keys, failure reasons, roles, tool names and plan-print features,** all inert, so no later wave edits `bin/audit`, `orchestrate.sh`, `run-config.mjs` or the registries that a new reason, role or tool touches. A reserved flag is shown by `--plan` and **refused on a real run** until its wave lands, so a safety flag such as `--max-minutes` is never silently ignored.
- **A wave-check runner, a coverage gate and a plan linter,** wired into CI, so "full test coverage" and "parallel-ready" are checked by tools and not by reading.

No review behaviour changes. A run that passes none of the new flags produces the same findings, adjudication and report as today (proved in W20-10).

5. `npm run check:w25` → "reserved: filled by W25", exit 0. `npm run check:v2` runs every filled check of the series.

## Risks and rollback

- **The seam wraps every Docker-path session.** A defect there affects every run. Mitigation: `OMNI_NO_MW=1` bypass (tested), a no-module identity test, the neutrality e2e. Rollback: revert the wave merge. No data migration exists.
- **The host path is not covered.** `--no-docker` runs and `./bin/audit demo` without Docker bypass the seam; the plan's features are Docker-path features and say so in `--plan`.
- **A reserved flag that does nothing could mislead.** It is shown as reserved by `--plan` and refused on a real run.
- **The coverage baseline can rot.** It may only be raised; lowering needs a recorded reason.
